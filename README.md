# Mini Redis Hash

使用 Go 标准库实现的单机 Hash 服务，面向学习和面试。通过 TCP 接收 RESP2 命令请求，使用 `sync.RWMutex` 保证单条命令的原子性，通过同步追加日志支持 kill -9 后恢复数据。

## 启动

需要 Go 1.22 或更新版本，无第三方依赖。

```sh
go run ./cmd/mini-redis
```

默认监听 `127.0.0.1:6380`，可以指定地址：

```sh
go run ./cmd/mini-redis -addr 127.0.0.1:6381
```

默认使用当前工作目录下的 `appendonly.aof` 保存数据。重启必须使用同一文件，可以通过 `-aof` 显式指定已存在目录中的路径：

```sh
go run ./cmd/mini-redis -addr 127.0.0.1:6380 -aof /path/to/data/appendonly.aof
```

当前持久化实现使用 Linux `flock`，运行目标为本地 Linux 文件系统。日志文件以进程级排他锁保护，同一文件同时只能被一个服务实例使用。路径错误、锁冲突或日志损坏会导致启动失败。服务在完整恢复之后才处理命令；恢复过程中监听端口可能已绑定，但不会响应请求。

收到 SIGINT（Ctrl+C）或 SIGTERM 时关闭监听器和客户端连接，并等待连接处理退出。数据保留不依赖正常停机钩子。

## 使用

在安装了 redis-cli 的环境中，可以执行以下命令。redis-cli 是可选客户端，不是服务端运行依赖。

```sh
redis-cli -p 6380 HSET user:1 name 张三 age 20
# 返回 2：新增两个字段
redis-cli -p 6380 HGET user:1 name
# 返回 张三
redis-cli -p 6380 HSET user:1 age 21
# 返回 0：更新已有字段
redis-cli -p 6380 HGETALL user:1
# 返回全部字段和值，顺序不保证
redis-cli -p 6380 HDEL user:1 age
# 返回 1
redis-cli -p 6380 DEL user:1
# 返回 1
```

## 命令语义

命令名称不区分大小写；键、字段和值区分大小写且支持任意字节，包括空字符串、NUL 和 CRLF。

| 命令 | 返回值与行为 |
| --- | --- |
| `HSET key field value [field value ...]` | 返回新增字段数；自动创建 Hash；重复字段以最后一个值为准，只计一次新增 |
| `HGET key field` | 返回值；不存在返回 RESP null bulk string，与空字符串不同 |
| `HDEL key field [field ...]` | 返回实际删除字段数；重复或不存在的字段不重复计数；删除最后一个字段时移除键 |
| `HEXISTS key field` | 存在返回 1，否则返回 0 |
| `HGETALL key` | 返回交替排列的字段和值；无固定顺序；键不存在时返回空数组 |
| `HLEN key` | 返回字段数；键不存在返回 0 |
| `DEL key [key ...]` | 返回实际删除的键数；重复或不存在的键不重复计数 |
| `PING [message]` | 无参数返回简单字符串 PONG；有参数返回该参数的 bulk string |

参数数量错误和未知命令返回 RESP 错误，连接仍可继续使用。服务先完整解析并验证参数，再执行命令；错误或不完整请求不会部分应用写入。

## 工程边界

- 一个进程、一个节点、一个逻辑数据库，仅支持 Hash 数据类型。
- 内存结构为 `map[string]map[string]string`；全局读写锁覆盖每条完整命令。多个查询可并发执行，写操作独占锁。多条独立命令之间不提供事务保证。
- 每个连接由一个 goroutine 按请求顺序处理，支持 TCP 分包、粘包与流水线。网络读写均在存储锁外；`HGETALL` 在读锁内构造结果快照，释放锁后编码并发送。
- 请求只支持 RESP2 的非空数组，元素必须为非 null bulk string。不支持 inline 命令、嵌套请求或 RESP3。
- 单条请求（含协议头）最多 8 MiB，最多 1024 个参数（含命令名），单个长度头最多 64 字节。协议错误或超限返回错误后关闭该连接。
- 最多 128 个活动连接，超出的连接直接关闭。每条请求读取期限为 5 分钟，响应写入期限为 30 秒；超时关闭连接。
- 未设置存储总内存上限或自动淘汰策略；请求限制不等于总内存限制。大型 `HGETALL` 仍可能占用较多内存并延迟写入。
- 不含复制、集群、TTL、事务、认证或完整 Redis 客户端兼容。客户端可能发送的 `AUTH`、`SELECT`、`HELLO`、`CLIENT` 等命令均未实现。
- 命令行服务默认启用持久化；内部 `Serve(ctx, listener)` 保留纯内存调用方式，`Serve(ctx, listener, aofPath)` 使用持久化。
- 不设 QPS 门槛，不做压力测试或性能 benchmark；100 连接、10 万字段不作为本次验收承诺。

## 数据保留与故障边界

每条有效的 `HSET`、`HDEL`、`DEL` 在写锁内依次完成：追加日志、文件 `Sync`、修改内存。只有这些步骤完成后才返回成功，保证日志顺序与内存修改顺序一致；查询及参数错误不写日志。

- **承诺**：在磁盘和文件系统正常、日志文件未被外部修改的条件下，客户端收到成功响应的写入在进程被 `kill -9` 后，使用同一日志重启可恢复。
- **结果未知**：客户端断连、超时或收到持久化错误时，命令可能已完整写入日志，重启后可能存在。没有请求去重或恰好执行一次的保证。
- **尾部中断**：启动时自动截断未写完的最后一条记录，并保留此前完整记录；截断后继续追加。
- **日志损坏**：完整记录的头部或内容校验失败、版本错误或非法命令会拒绝启动，不自动跳过记录；应保留文件并排查。部分初始化文件头可重新初始化。
- **磁盘错误**：运行中日志写入或 Sync 失败会返回 `MISCONF`，该命令不修改当前内存，服务记录故障并拒绝所有后续写命令，读取仍可用。排除磁盘问题后通过重启恢复；重启是否成功取决于日志是否可恢复。
- **格式**：带版本标识、记录长度、头部和内容 CRC32 校验的私有二进制格式，不兼容 Redis AOF 工具。CRC 用于检测意外损坏，不提供防篡改保证。
- **当前范围**：不承诺系统断电、磁盘损坏或整机丢失时的数据保留。不含快照、日志重写或备份；文件会持续增长，启动需要完整回放。每次写入都同步磁盘，可能增加延迟，未设性能指标。

## 正确性验证

```sh
go test -race ./...
go vet ./...
```

测试覆盖命令语义、参数错误、空值和二进制数据、Hash 隔离、查询快照、多字段写入原子性、并发数据竞争、协议长度校验、截断请求、TCP 分包与流水线、多个客户端共享数据，以及服务取消时关闭连接。

持久化测试包含真实子进程 SIGKILL 后重启及再次写入恢复、并发写入恢复、所有尾记录截断位置、头部和内容损坏、日志排他锁，以及注入部分写入和 Sync 失败。

验证环境未安装 redis-cli，已通过原始 RESP2 的 TCP 集成测试；未直接验证特定 redis-cli 版本。

## 代码入口

- `cmd/mini-redis/main.go`：监听地址、启动和信号处理。
- `internal/redis/server.go`：连接管理、请求处理和退出。
- `internal/redis/protocol.go`：RESP2 解析与响应编码。
- `internal/redis/store.go`：Hash 命令与读写锁。
- `internal/redis/aof.go`：同步追加日志、启动恢复、校验与排他锁。
