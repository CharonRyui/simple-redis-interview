# Mini Redis 设计

状态：内存版本、数据保留、存储计账限制及手动快照已完成。验收仅包含正确性和故障恢复验证。

## 已确认的范围

- 用途：学习／面试项目。
- 技术栈：Go，使用标准库，无第三方依赖。
- 数据模型：Redis Hash；一个键对应一组字段，每个字段对应一个值。
- 部署：单进程、单节点、一个逻辑数据库，支持多个客户端。
- 接口：TCP + RESP2 必要子集，按 redis-cli 的 RESP2 命令请求格式处理约定命令，不承诺完整 Redis 客户端兼容。
- 命令：HSET、HGET、HDEL、HEXISTS、HGETALL、HLEN、DEL、PING，以及手动同步快照 SAVE。
- 命令语义沿用 Redis：HSET 支持多字段写入，返回新增字段数；HDEL 支持多字段删除；DEL 支持多键删除；删除最后一个字段时移除 Hash；HGET 区分不存在与空字符串；HGETALL 不保证顺序。
- 并发：使用简单读写锁，保证单条命令原子性。
- 验收：只验证正确性，不做压力测试、性能 benchmark 或固定 QPS 承诺。此前建议的 100 个连接、10 万字段不作为验收指标。
- 不包含主从复制、集群、事务、TTL、自动淘汰或完整 Redis 命令兼容。
- 已实现数据保留，覆盖 kill -9；客户端收到成功响应的写入在使用同一日志文件重启后可恢复。前提为磁盘和文件系统保持正常、日志未被外部修改；不承诺断电、磁盘损坏或机器丢失下的数据保留。

## 数据保留扩展

保留 Go 标准库及全局读写锁；不增加压测或性能 benchmark。

- 写入顺序：参数验证 → 获取写锁 → 追加完整命令记录 → 文件 Sync 成功 → 应用内存修改 → 释放锁 → 返回成功。日志和内存修改使用相同串行顺序，单条多字段命令对应一条日志记录。
- 采用带版本、长度、头部及内容 CRC32 校验的追加日志；记录 HSET、HDEL、DEL，不记录查询和错误命令。日志格式为本项目私有格式，不兼容 Redis AOF 文件。
- 启动时先验证和回放日志，再接受请求；恢复期间不对外提供部分数据。恢复后从最后一条有效记录继续追加。
- -aof 路径参数默认使用当前工作目录下的 appendonly.aof；恢复必须使用同一文件。目标运行环境为本地 Linux 文件系统，通过 flock 加进程级排他锁，避免两个实例同时写同一文件。
- 成功响应只在 Sync 成功后发出。客户端未收到成功响应的命令结果仍可能在恢复后存在，不承诺请求去重或恰好执行一次。
- 默认自动截断末尾不完整记录；完整记录校验失败、版本错误或非法命令则拒绝启动，不跳过损坏记录。
- 运行时日志写入或 Sync 失败后，该命令不修改内存，服务返回 MISCONF 并停止后续写入；保留读取，同时输出错误原因。重启后重新回放日志；失败命令可能已完整记录，恢复后可能存在。
- 增加手动快照及对应检查点之后的日志回放；不增加日志重写、备份、复制或自动损坏文件修复。保留完整 AOF，日志可能持续增长；启动仍需扫描快照对应的日志前缀进行校验。
- 已验证：真实子进程成功写入后 SIGKILL 并重启，验证新增、覆盖、字段删除、整键删除；所有尾记录截断位置；校验损坏；写入失败和 Sync 失败；日志排他锁；恢复后继续写入及再次重启。并发写入恢复也纳入验证。

## 存储限制和快照

- 命令行默认存储计账上限 64 MiB，可通过 -max-storage-bytes 配置，0 为不限。每个 Hash 计 len(key)+64，每个字段计 len(field)+len(value)+64。字节额度不等同于进程 RSS 或磁盘空间限制。
- HSET 在写锁内按完整命令的最终状态预检，重复字段按最后值计账；超限返回 OOM，内存和日志均不修改。覆盖缩小、HDEL、DEL 释放额度。恢复后检查最终数据，超限拒绝启动，不静默丢弃数据；恢复峰值内存不受此上限保证。
- SAVE 在写锁内流式保存完整快照，无后台或定时任务；保存期间其他存储命令等待。默认路径为 AOF 路径加 .snap，可使用 -snapshot 配置。
- 快照格式含版本、AOF 截止位置、日志前缀 SHA-256、单字段记录及整体 SHA-256。通过临时文件、文件 Sync、原子 rename 及目录 Sync 发布。
- 不修改已有 AOF 格式，不截断或重写日志。启动验证快照和 AOF 前缀，加载快照并回放后续命令；无快照则完整回放。快照依赖匹配的完整 AOF，不能单独作为恢复来源。
- 损坏、截断或不匹配的正式快照拒绝启动；临时文件不参与恢复。普通 SAVE 失败不禁用 AOF 写入；AOF 已故障时禁止 SAVE，避免保存与日志不一致的状态。
- 已验证容量边界、拒绝原子性、额度回收、并发限制、恢复计账、快照前后修改和删除、并发保存、校验错误，以及快照保存完成和临时文件写到一半时的 SIGKILL 恢复。

## 实现方案

数据存于 `map[string]map[string]string`，由全局 `sync.RWMutex` 保护。每个连接由一个 goroutine 顺序处理请求；完整解析和参数验证发生在执行命令之前，写锁覆盖一条命令的所有修改。读锁覆盖查询及结果快照构建，网络编码和发送在锁外完成。

TCP 处理支持分包、粘包和流水线。协议仅接收非空数组，数组元素为非 null bulk string。命令参数错误和未知命令返回错误并保留连接；协议错误或请求超限返回错误后关闭连接。

收到 SIGINT 或 SIGTERM 后，服务停止接受连接，关闭活动连接并等待处理退出。

## 实现默认值

以下是未单独指定部分采用的默认值，均记录在 README：

- 监听地址：`127.0.0.1:6380`，通过 `-addr` 修改。
- 请求总大小：最多 8 MiB，包含协议头。
- 参数数量：最多 1024 个，包含命令名。
- 长度头大小：最多 64 字节。
- 活动连接：最多 128 个，超出的连接直接关闭。
- 每条请求读取期限：5 分钟；响应写入期限：30 秒。

存储计账上限不构成进程总内存上限；大型 HGETALL、协议缓冲、Go map 与 GC 均有额外开销。快照保存会阻塞其他存储操作，AOF 大小没有上限。

## 正确性验证

- 命令新增、覆盖、查询、删除与返回值。
- 不存在与空字符串的区别、空键与字段、二进制数据。
- 重复字段和重复键计数、删除最后一个字段时移除键。
- 参数错误不修改数据，Hash 之间相互隔离。
- HGETALL 返回一致快照，多字段写入不会被读取到中间状态。
- 竞态检测下的并发读写、多个 TCP 客户端共享数据。
- RESP2 长度校验、协议错误、截断请求、TCP 分包和流水线。
- 服务取消后关闭监听器与活动连接。
