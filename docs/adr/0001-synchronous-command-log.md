# 使用同步命令日志保留已确认写入

为了让客户端已收到成功响应的写入在进程被 SIGKILL 后仍可恢复，所有写命令在同一写锁内先追加日志并完成文件 Sync，再修改内存并返回成功。选择每次写入同步而非周期同步，接受写入延迟及锁等待增加，以避免已确认写入存在未同步窗口；采用带版本和头部及内容校验的私有日志格式而非直接记录 RESP，以便检测意外损坏，代价是不兼容 Redis AOF 工具。

启动时只自动截断末尾不完整记录，完整记录校验失败则拒绝启动。运行时持久化失败后禁止继续写入并保留读取，避免在不确定日志状态上追加数据；未收到成功响应的命令仍可能在恢复后存在。本阶段只覆盖磁盘和文件系统正常时的进程故障，不承诺断电或磁盘损坏恢复，也不实现日志重写或请求去重。
